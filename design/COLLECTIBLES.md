# 收藏摆件 · 精细建模与验收

## 莫妮卡公寓

以用户明确选定的「紫墙、蓝厨房」剖面图为户型基准，制作厨房、客厅和后方窗区的开放式微缩场景。原生模型保留 1,484 个零件。主体纵深大于宽度，前沿分成入口与客厅两个错位边界，后方窗区向厨房后侧继续延伸。

- 左墙的炉灶与窗下水槽、青蓝色围窗开放餐具架、后墙奶油色双门吊柜、L 形木台面、锅具吊杆，以及厨房右后端的冰箱和照片磁贴。木梁沿厨房前沿与右侧转折，立柱位于沙发外侧。
- 紫色入口门、黄色曲线窥孔框与角部卷饰、门板线脚、门把手；后方走廊、卧室门、青绿门、抬高地台与地毯。
- 独立拼接并沿边界裁切的鱼骨木地板、落地大窗、窗格、竹木帘、束起的织物窗帘、绿坐垫窗台和小书桌。
- 奶油色沙发沿房间纵向摆放、朝向右墙电视；茶几位于两者之间，扶手椅在后方地台前侧，圆餐桌在厨房前方。保留独立填充坐垫、包边、拼布抱枕、红格毛毯、绿色脚凳和两只彩绘矮凳。
- 后方左侧为带紫门和青绿门的走廊，右侧为大窗、绿窗台坐垫与小书桌；参考图中的圣诞树和礼物位于抬高窗区，扶手椅在树的前方。
- 圆餐桌、四把不同颜色的细杆餐椅、水果、杯碟、锅壶、木勺、书刊、盆栽和白色小花。

织物与木材使用可导出的烘焙法线贴图；地毯、拼布、格纹、木纹与砖墙贴图由确定性脚本生成。原生家具由 `collectible_monica.py` 制作，实际户型、摆放变换与建筑重建统一由 `collectible_monica_layout.py` 应用；GLB 布局文件保留参考户型轮廓。

补充参考：[LEGO Friends Apartments 展示](https://www.lego.com/en-us/product/the-friends-apartments-10292)。

## 千年隼

以用户提供的俯视图、实物模型照片及 LEGO UCS 外观为参考。按照 84 × 60 × 21 cm 的展示尺寸比例制作，原生文件保留分层、命名的外壳和机械部件。

- 带中央货舱缺口的浅锥形船体、上下装甲边缘与裸露机械夹层。
- 三圈径向分块装甲、独立小瓦片、凸点、维修盖板、通风百叶、暗红与沙色补丁、绕开散热井的成组管线和固定夹。
- 两条舰艏从宽阔三角肩部向窄平叉尖收缩，外缘有明确折线；中间前体延伸至舰艏前段，中央开口约占总长的六分之一。四个检修井随三角肩部收窄依次内移，配合沿轮廓布置的管线、格栅和薄鼻端护板。
- 六座真实凹进的冷却井、双层井圈、逐片格栅与紧固件；后部连续蓝色驱动条和外围防护栅。
- 收回圆盘外缘以内的偏置驾驶舱、通道分段装甲、分片烟色玻璃与窗框、侧面多层停靠口、四联炮及炮口、带细刻线的凹面雷达碟、背部加强肋和铰接支架。
- 七组带轴销、液压杆、斜撑与脚垫纹路的起落支撑，以及底部维修盖板，支持翻到背面和底部查看。

这是针对网页制作的 UCS 风格外观模型。舰艏轮廓由 `collectible_falcon_forebody.py` 单独定义；圆盘长宽接近一致，整体尺寸依据实际顶点包络校准。补充参考：[LEGO UCS 75192 展示与尺寸](https://www.lego.com/en-us/product/millennium-falcon-75192)、[LEGO 官方说明册中的俯视结构图，第 5 页](https://www.lego.com/cdn/product-assets/product.bi.additional.info.pdf/75192_X_Digital%20Booklet%20-%20DE.pdf)。

## One Wish Willow

纸盒以用户指定的 [One Wish Willow 互动网站](https://onewishwillow.app/zh/) 及最新修正意见为准，制作长条三棱柱纸盒，保留纸张厚度、内外表面、长边压痕和闭合左端。右端为三角形开口；已删除抽出的内托、纸舌和外伸纸片，纸张全部位于纸盒两端平面以内。

柳条按实物参考制作黑色中空木质结构，四个方向分别分布 5、6、4、5 个大小、间距和倾斜不同的开孔，四面不再共享整齐的孔洞行列。端部保留不齐的分叉，孔口和外轮廓有细小不规则起伏，内部空腔真实贯通。大部分枝条位于纸盒内，从右侧开口露出约 8.6 cm；最终 GLB 的三角网格检查确认木质表面不穿过纸壁或左端盖。

印刷使用参考站公开展示的完整包装展开图，通过独立 UV 窗口映射三个长面与端盖；转到背面时图文保持正向。包装图的出处记录在 [资产来源](../public/models/collectibles/ASSET-CREDITS.md)。参考站的三维网格没有导入本项目。

## 安督利尔与接骨木魔杖

安督利尔以用户提供的正面佩剑照片确定轮廓，包含约 1.346 m 的长剑、双刃斜面、真实凹槽、皮革螺旋缠柄、银色长剑首、镂空叶形剑首与开孔护手。剑身的 73 组刻纹轮廓从用户照片读取并转为矢量几何，两面保留刻纹、日月与七星细节；没有将另一种字体当作精灵文字。胡桃木盾形背板、金色树纹和软衬挂钩属于独立展示装配。

接骨木魔杖按十五英寸（38.1 cm）长度制作，参考 [Noble Collection](https://noblecollection.com/Item--i-PRP-HP-7145) 和用户提供的照片。连续弯曲木身有六处大小不同的瘤节、168 处真实表面凹坑、细小木纹色差、喇叭形尾端及浅色刻纹环。两只黄铜软衬托架按对应处木杆半径定位，木底座位于书柜顶层。

两者的展示部件使用独立材质及 `display_support` GLTF 标记。独立查看窗口只改变自己的场景副本，隐藏展架不会影响房间中的陈列。新材质继续接受日夜灯光，未使用不受光的贴色材质。

独立查看窗口根据当前模型的真实尺寸直接设置缩放与中心位置，避免 `Center` 缓存上一个摆件的高度后裁掉长剑。`lib/collectible-inspection.ts` 按相机角度、透视投影和窗口宽高计算完整取景，正面查看、重置角度及重新打开均使用同一规则。横屏、竖屏及摆件切换时，模型包络保留约 8.5% 的边缘空间；放大后可用重置恢复完整视图。

## 重建与检查

```powershell
python scripts/blender/make_collectible_textures.py
& 'D:\Program Files (x86)\Steam\steamapps\common\Blender\blender.exe' --background --factory-startup --python-exit-code 1 --python scripts/blender/build_collectibles.py
node scripts/compress-models.mjs
& 'D:\Program Files (x86)\Steam\steamapps\common\Blender\blender.exe' --background --factory-startup --python-exit-code 1 --python scripts/blender/check_collectible_clearance.py
npm run typecheck
npm run test:interaction
npm run test:performance
npm run test:clearance
npm run test:public
npm run build:github
```

原生文件在 `design/collectibles/`，GLB、布局与贴图在 `public/models/collectibles/`。`lib/collectibles.ts` 定义共享摆放变换，模型单位为米，既有房间每单位约为 0.45 m。公寓保持原陈列中心，旋转 90° 将长边沿书架排列；实际 31 cm 的短边位于书架深度内。网页与完整房间离线预览使用同一摆放变换。

`check_collectible_clearance.py` 对原生网格建立 BVH，检查独立家具、杯碟、灯具、盆栽、墙体、毛毯与沙发坐垫及包边，并核对飞船管路与散热组件。结构连接、装甲固定件等同一装配内部的连接接触单独处理。本次 943 组检查通过，[验收记录](collectible-clearance.json) 保留原生文件 SHA-256；重新运行时输出在 `work/qa/miniature-clearance.json`。

形体回归检查直接对最终 GLB 发射射线：核对千年隼前体填充、前端短缺口和窄叉尖；核对公寓后左侧空缺、向后延伸的窗区、错位前沿与真实抬高的地板。

完整房间检查使用最终 GLB 的实际三角网格，覆盖所有独立摆件与既有物品、185 条取放与镜头路径、306,185 个姿态及连续扫过体积。尺寸、归一化原点、顶点和着色属性的有限值、受光材质、文件体积与版本哈希另行校验。`check_fantasy_collectibles.py` 另行核对剑的实体闭合性、魔杖与软托接触、柳条单一连通结构，并生成近景和房间日夜渲染。

本轮 69 项自动检查、类型检查及生产构建通过。模型版本、原生文件哈希和几何验收计数记录在 [藏品验收记录](fantasy-collectibles-verification.json)。新增回归检查涵盖切换藏品后的居中、四种窗口比例的透视取景、柳条四面的实际孔洞分布，以及插入纸盒后的网格防穿模。魔杖底座完整位于柜顶前沿，避开原有花盆、藤蔓与档案盒把手；剑的背板位于墙面前方，未嵌入墙体。

先运行 `node scripts/export-inspection-views.mjs`，再用 Blender 执行 `scripts/blender/render_inspection_views.py`。后者从 `work/qa/inspection-framing.json` 读取网页取景函数导出的相机位置，检查原生柳条的封闭性、连通性和纸托删除情况，再渲染长剑与纸盒在横屏、竖屏中的完整视图。输出在 `work/qa/*-framed-*.png`，属于 Blender 检查图。

`render_collectible_details.py` 渲染正面、背面、俯视、底部和近景；`render_details.py -- --records` 检查放回完整房间后的日夜效果。离线渲染是原生源文件的检查图，不能作为浏览器截图。浏览器预览权限在本会话中被拒绝，网站的浏览器视觉与端到端交互验收仍由用户审核；发布结果通过公开 HTTP 文件与资产哈希核对。

夜间黑色外部、白天纯白空间、五秒停留导航和折叠菜单继续保留。黑猫仍只保留 [设计方案](BLACK-CAT-PROPOSAL.md)。
