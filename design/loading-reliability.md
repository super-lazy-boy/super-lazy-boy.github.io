# 房间首屏加载与恢复

2026-11-14：针对电脑 Chrome / Edge 中「100% 闪烁，房间未显示」及首次打开慢的反馈。

已核查线上入口、主模型和 TARDIS 关键纹理均返回 HTTP 200，响应类型正确。该检查不代表用户所在网络的实际传输速度。

旧界面使用 Three 全局 LoadingManager 的资源计数。自动检查已重现：一个文件加载结束时进度到 100%，随后发现另一张纹理时重新变为 0%，再到 100%。这不表示 GLB 解码或房间绘制已经完成；不能仅靠该计数判断房间是否可以显示。此行为与反馈中的进度闪烁吻合，未将其当作用户设备白屏的唯一已证实原因。

本轮修改：

- 主房间与每个原生摆件使用按完整版本 URL 缓存的稳定 Promise；切换查看窗口或重建画布可复用已解码资产。失败项单独清除，重试时重新请求，成功项保留。
- 主房间使用实际下载字节、解码与画面准备阶段显示进度；下载结束最多为 90%，解码为 92%，等待绘制为 96%。只有房间内容提交、着色器准备完成，并经过后期处理的首次绘制后才移除加载提示。后台摆件和纹理请求不重启首屏进度。
- 下载字节更新只通知加载提示。画布控制器只订阅阶段变化，避免每个网络数据块都重渲染场景并重建后期处理通道。
- 使用 `compileAsync` 提前准备材质程序，并匹配后期处理所用的线性渲染目标，避免先编译另一组输出色彩空间程序。
- 房间首先请求 11,323,476 字节的主 GLB。其余约 12.7 MB 的六个原生 GLB 和程序式 TARDIS 在首帧后逐件装入，均保留原模型。某件摆件失败时继续显示房间和其余摆件，可独立重试。
- 下载停滞或解码超时、HTTP 错误、HTML 替代响应、截断 GLB、嵌入纹理失败均进入错误状态。另行监测解码后长时间没有绘制及 WebGL 上下文丢失，提供重新打开入口，避免无限显示完成百分比。
- TARDIS 的木纹明暗、窗玻璃和顶灯复用不可变像素数据；删除原先计算后并未绑定到材质的木纹粗糙度数组。保留全部 1024 × 1024 纹理、材质参数和磨损着色器。纹理对象仍按模型创建和释放，避免一个查看窗口释放另一个窗口的 GPU 资源。像素 SHA-256 与修改前逐项相同。
- 原生 GLB、贴图文件、DPR、SMAA、环境遮蔽、灯光、阴影设置及摆放均未降低或更改。复用项目已有 GLTFLoader 与一个共享解码器，避免重复引入另一套解析器。
- 发布版本增加应用源码指纹。代码修正也会生成新的审核链接，便于区分旧缓存页面和当前加载程序。

验证：`npm run typecheck`、`npm run test:loading`、`npm run test:interaction`、`npm run test:clearance`、`npm run test:performance`、`npm run test:public` 和生产构建。合计 81 项自动检查，包括所有最终 GLB 的真实解析、PNG/JPEG 图像尺寸与原三角面数量、TARDIS 原像素哈希、稳定缓存、超时中止与重试、错误响应，以及实际 React / R3F 生命周期中的异步着色器准备、首次绘制通知和下载更新隔离。后者使用 CPU 渲染器替身，没有运行浏览器或模拟实机 GPU。

线上发布以版本、程序包和资产哈希核对。未录制用户 Chrome / Edge 的网络或 GPU 轨迹，因此不承诺固定加载秒数，也未将这些自动检查描述为浏览器实机复测。
